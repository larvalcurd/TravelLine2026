# BookingApp — REST API для бронирования

Backend-сервис для каталога объектов размещения, категорий номеров, поиска доступности и бронирований. Реализован на ASP.NET Core с разделением на Domain / Infrastructure / WebApi.

## Что реализовано

- CRUD объектов размещения (`Property`) и категорий номеров (`RoomType`);
- поиск доступных категорий по городу, датам, количеству гостей и опциональному лимиту цены;
- учёт физического количества номеров и пересечений дат активных бронирований;
- создание бронирования с проверкой объекта, категории, вместимости и доступности на период;
- фиксация стоимости и валюты на момент создания бронирования;
- фильтрация бронирований и логическая отмена через `IsCanceled`;
- Swagger UI и XML-комментарии к API.

## Стек

- C# / .NET 10;
- ASP.NET Core Web API;
- Entity Framework Core 10;
- SQLite (`Data Source=booking.db`);
- FluentValidation;
- Swashbuckle + MicroElements.Swashbuckle.FluentValidation.

## Архитектура

```text
BookingApp/
├── BookingApp.Domain/          # сущности, бизнес-правила, контракты сервисов и репозиториев
├── BookingApp.Infrastructure/  # EF Core DbContext, конфигурации, репозитории, начальные данные
└── BookingApp.WebApi/          # контроллеры, DTO, маппинги, валидаторы, middleware, запуск
```

Бизнес-проверки вынесены в сервисы Domain: `PropertyService`, `RoomTypeService`, `SearchService`, `ReservationService`. Infrastructure реализует контракты репозиториев через EF Core. WebApi работает с DTO и не содержит доступа к `DbContext` напрямую.

## Предметная модель

| Сущность | Основные данные |
| --- | --- |
| `Property` | название, страна, город, адрес, широта и долгота; содержит категории номеров. |
| `RoomType` | ссылка на `Property`, название, цена за ночь, валюта, диапазон гостей, число физических номеров, сервисы и удобства. |
| `Reservation` | ссылки на объект и категорию, даты и время заезда/выезда, данные гостя, число гостей, итоговая сумма, валюта и признак отмены. |

Идентификаторы — `Guid`. Списки сервисов и удобств нормализуются при сохранении: пустые строки исключаются, остальные обрезаются по краям.

## API

Базовый URL для HTTP-профиля: `http://localhost:5070`.

### Объекты размещения

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/api/properties` | Список объектов. |
| `GET` | `/api/properties/{id}` | Объект по GUID. |
| `POST` | `/api/properties` | Создать объект. |
| `PUT` | `/api/properties/{id}` | Обновить объект. |
| `DELETE` | `/api/properties/{id}` | Удалить объект, если нет активных бронирований. |

Для создания и обновления передаются `name`, `country`, `city`, `address`, `latitude`, `longitude`. Координаты ограничены диапазонами широты `[-90; 90]` и долготы `[-180; 180]`.

### Категории номеров

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/api/properties/{propertyId}/roomtypes` | Категории указанного объекта. |
| `POST` | `/api/properties/{propertyId}/roomtypes` | Создать категорию для объекта. |
| `GET` | `/api/roomtypes/{id}` | Категория по GUID. |
| `PUT` | `/api/roomtypes/{id}` | Обновить категорию. |
| `DELETE` | `/api/roomtypes/{id}` | Удалить категорию, если нет активных бронирований. |

Тело запроса содержит `name`, `dailyPrice`, `currency`, `minPersonCount`, `maxPersonCount`, `totalRoomsCount`, `services`, `amenities`. Проверяются положительная цена, корректный диапазон гостей, положительное число номеров и трёхсимвольная валюта.

### Поиск доступности

```http
GET /api/search?city=Moscow&arrivalDate=2026-07-10&departureDate=2026-07-12&guests=2&maxPrice=7000
```

Обязательны `city`, `arrivalDate`, `departureDate`, `guests`; `maxPrice` опционален. Дата выезда должна быть позже даты заезда.

Поиск учитывает город без регистра, вместимость категории и максимальную цену. Для каждой категории считаются активные бронирования с пересечением периода по правилу:

```text
arrival < existingDeparture && departure > existingArrival
```

Если свободные номера есть, ответ содержит их количество, число ночей и стоимость за период. Результаты сортируются по цене за ночь, затем по названию объекта и категории.

### Бронирования

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `POST` | `/api/reservations` | Создать бронирование. |
| `GET` | `/api/reservations` | Список бронирований с фильтрами. |
| `GET` | `/api/reservations/{id}` | Бронирование по GUID. |
| `DELETE` | `/api/reservations/{id}` | Логически отменить бронирование. |

Пример тела для создания:

```json
{
  "propertyId": "11111111-1111-1111-1111-111111111111",
  "roomTypeId": "aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaa1",
  "arrivalDate": "2026-07-20",
  "departureDate": "2026-07-22",
  "arrivalTime": "14:00:00",
  "departureTime": "12:00:00",
  "guestName": "Иван Иванов",
  "guestPhoneNumber": "+79990000000",
  "guestCount": 2
}
```

Перед созданием проверяются существование объекта и категории, их взаимосвязь, допустимое количество гостей и свободные номера на период. Итоговая сумма рассчитывается по текущему `dailyPrice` категории; валюта также копируется в бронирование.

Список поддерживает `propertyId`, `roomTypeId`, `arrivalDateFrom`, `arrivalDateTo`, `guestName`, `guestPhoneNumber`, `includeCanceled`. По умолчанию отменённые записи не возвращаются. Фильтрация по имени и телефону — частичное совпадение; имя — без учёта регистра. Результат сортируется по дате и времени заезда.

## Валидация и ошибки

Входные DTO проверяются FluentValidation до передачи в сервисы. Доменные сервисы дополнительно валидируют бизнес-правила, поэтому ограничения действуют и вне HTTP-слоя.

`ExceptionHandlingMiddleware` возвращает JSON вида `{"error":"..."}` и сопоставляет исключения кодам:

| Ситуация | HTTP-статус |
| --- | --- |
| Объект, категория или бронирование не найдены | `404 Not Found` |
| Некорректные данные или нарушено бизнес-правило | `400 Bad Request` |
| На период не осталось свободных номеров | `409 Conflict` |
| Непредвиденная ошибка | `500 Internal Server Error` |

## Запуск

Конфигурация подключения находится в `BookingApp.WebApi/appsettings.json`. Текущая БД — SQLite (`booking.db`).

```powershell
dotnet run --project .\webapi-task\BookingApp\BookingApp.WebApi\BookingApp.WebApi.csproj
```

Swagger UI: `http://localhost:5070/swagger`.

## Текущие ограничения

- нет аутентификации, авторизации, платежей и клиентского интерфейса;
- бронирование нельзя редактировать — доступны создание, получение и отмена;
- нет защиты от конкурентного создания последних свободных номеров;
- удаление `Property` и `RoomType` блокируется только активными бронированиями; отменённые не препятствуют удалению.
